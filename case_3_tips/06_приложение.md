## A. Диаграммы

### A.1. Схема системы

Исходник draw.io: `diagrams/system_scheme.drawio`.

Поток: **Клиент → Платформа → Эмулятор шлюза → Платформа → Клиент**. Платформа читает и изменяет данные в **Хранилище**, а каждый переход платежа передаёт в **Аудит**.

| Блок | Что это | Что передаёт |
|-|-|-|
| Клиент | браузер на телефоне | сканирование QR, выбор чаевых, подтверждение/отмена |
| Платформа | React + TypeScript + Vite | проверку QR, платёжный запрос, итог операции |
| Эмулятор шлюза | детерминированная функция | `SUCCESS`, `DECLINED` или `PENDING/GATEWAY_TIMEOUT` |
| Хранилище | исходные CSV + localStorage | мерчантов, сотрудников, QR, платежи |
| Аудит | журнал событий | action, переход статусов, сумму, actor, timestamp |

### A.2. ER-модель

Сущности: Merchant, Employee, QR, Payment, Report, AuditEvent. PK/FK и ограничения приведены в `08_errors.md` (исходный шаблон ER). Исходник диаграммы: `diagrams/er_model.drawio`.

Связи: Merchant 1:N Employee, Merchant 1:N QR, Employee 1:N QR, QR 1:N Payment, Merchant 1:N Report, Payment 1:N AuditEvent.

### A.3. Схема состояний платежа

Исходник draw.io: `diagrams/payment_states.drawio`.

```text
CREATED ── клиент подтвердил ──> PENDING ── шлюз: успех ──> SUCCESS
   │                              │
   │                              ├── шлюз: отказ ──> DECLINED
   │                              └── таймаут ──> PENDING + GATEWAY_TIMEOUT
   │                                                     │
   └── клиент отменил ──> CANCELED                       └── проверка статуса ──> SUCCESS
```

Отмена разрешена только из `CREATED`; из `PENDING` возвращается `CANCEL_NOT_ALLOWED`.
`used = true` у QR ставится только при `SUCCESS`, поэтому `DECLINED` и `CANCELED` не сжигают чек: на экране статуса есть «Попробовать снова» (связь `QR → Payment` = 1:N).

## B. Таблицы

### B.1. Правила QR и платежа

| ID | Правило | Обоснование |
|-|-|-|
| Q-1 | HMAC-подпись должна совпасть | исключает подделку payload |
| Q-2 | `exp >= now` | ограничивает время жизни ссылки |
| Q-3 | QR/nonce не использован | предотвращает replay |
| Q-4 | Мерчант `ACTIVE` | запрещает операции заблокированного заведения |
| Q-5 | `receipt_id` совпадает | исключает подмену чека |
| Q-6 | `0 <= tip_pct <= 50` | реализует ограничение ТЗ |
| P-1 | `0 < base_amount <= 1 000 000` | отсекает некорректные суммы |
| P-2 | Повтор ключа возвращает исходный платёж | исключает дубли |
| P-3 | `amount_total <= 2 000 000` | верхняя защитная граница операции |
| P-4 | Нет отмены из `PENDING` | запрещает отмену после начала подтверждения |

### B.2. Ситуация → код → HTTP → retryable

| Ситуация | Код ошибки | HTTP | retryable |
|-|-|-|-|
| Подпись QR не совпала | `INVALID_QR` | 422 | нет |
| QR истёк | `QR_EXPIRED` | 410 | да, с новым QR |
| nonce/QR использован | `QR_USED` | 409 | нет |
| Мерчант заблокирован | `MERCHANT_BLOCKED` | 403 | нет |
| Мерчант ещё не активирован | `MERCHANT_NOT_ACTIVE` | 403 | да, после активации |
| Чек не соответствует QR | `RECEIPT_MISMATCH` | 422 | нет |
| Чаевые вне 0–50 % | `TIP_OUT_OF_RANGE` | 422 | да, после исправления суммы |
| Сумма чека вне диапазона | `AMOUNT_OUT_OF_RANGE` | 422 | да, после исправления суммы |
| Отмена из `PENDING` | `CANCEL_NOT_ALLOWED` | 409 | нет |
| Таймаут шлюза | `GATEWAY_TIMEOUT` | 200, статус `PENDING` | да, проверка статуса |
| Отказ карты | `CARD_DECLINED` | 200, статус `DECLINED` | да, другой способ/новый платёж |
