# Правила QR и платежа — кейс 3

## Проверки QR

| ID | Проверка | Действие | Код ошибки |
|-|-|-|-|
| Q-1 | `signature` совпадает с HMAC-SHA256 от payload | продолжить | — |
| Q-2 | `exp >= now` | продолжить; иначе отклонить | `QR_EXPIRED` |
| Q-3 | `nonce` и QR ещё не использованы (`used = false`) | продолжить; при повторе отклонить | `QR_USED` |
| Q-4 | `merchant.status = ACTIVE` | продолжить; для `BLOCKED` отклонить | `MERCHANT_BLOCKED` |
| Q-5 | `receipt_id` запроса совпадает с `receipt_id` в QR | продолжить; иначе отклонить | `RECEIPT_MISMATCH` |
| Q-6 | `0 <= tip_pct <= 50` | продолжить; значение вне диапазона отклонить | `TIP_OUT_OF_RANGE` |

## Правила платежа

| ID | Условие | Действие | Код ошибки |
|-|-|-|-|
| P-1 | `base_amount <= 0` или `> 1 000 000` | отклонить | `AMOUNT_OUT_OF_RANGE` |
| P-2 | Повтор переданного `idempotency_key` | вернуть существующий платёж, HTTP 200; дубль не создавать | — |
| P-3 | `amount_total > 2 000 000` | отклонить | `AMOUNT_OUT_OF_RANGE` |
| P-4 | Попытка отмены из `PENDING` | отклонить; отмена разрешена только из `CREATED` | `CANCEL_NOT_ALLOWED` |

Дополнительно сумма чека должна совпадать с суммой, связанной с QR. При совпадении ключа идемпотентности состояние не изменяется. В веб-интерфейсе значение выше 50 % автоматически ограничивается 50 %, после успешной оплаты пользователю предлагается оставить отзыв.
