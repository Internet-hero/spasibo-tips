## 2. Меры защиты

| ID | Угроза | Мера | Остаточный риск |
|-|-|-|-|
| U-1 | Подделка QR | HMAC-SHA256, серверное хранение секрета в production | низкий |
| U-2 | Replay | Одноразовый nonce/QR, `used`, TTL 24 часа | низкий |
| U-3 | Кража реквизитов | Только маска `****NNNN`, запрет PAN/CVV, разграничение доступа | низкий |
| U-4 | Двойное списание | `idempotency_key`, возврат существующего платежа без дубля | низкий |
| U-5 | Манипуляция суммой | Связь QR с `receipt_id`, сверка `base_amount`, лимит чаевых 50 % | низкий |
| U-6 | Отсутствие аудита | Неизменяемый журнал действий, статусов, actor, суммы и времени | низкий |

## 3. RBAC — матрица прав

| Действие | Мерчант | Официант | Клиент | Администратор |
|-|-|-|-|-|
| Регистрация | да | по приглашению | не требуется | по назначению |
| Генерация QR | да | да, только на себя | нет | нет |
| Просмотр своих чаевых | да, по заведению | да, только своих | нет | только аудит |
| Сканирование QR | нет | нет | да | нет |
| Оплата чаевых | нет | нет | да | нет |
| Просмотр отчёта | да, своего заведения | только личный | нет | да |
| Блокировка мерчанта | нет | нет | нет | да |
| Изменение справочников | своего заведения | только своих данных | нет | всех |

В демо авторизация визуальная; перечисленные правила описывают целевую модель и клиентские ограничения интерфейса, а не production-защиту.

## 4. Аудит — структура события

| Поле | Тип | Пример | Зачем |
|-|-|-|-|
| `event_id` | string | `evt_0001` | уникальный ID |
| `payment_id` | string | `p_0001` | привязка к платежу |
| `qr_id` | string | `qr_001` | привязка к QR |
| `action` | enum | `payment_confirmed` | тип операции |
| `from_status` | enum/null | `PENDING` | предыдущее состояние |
| `to_status` | enum | `SUCCESS` | новое состояние |
| `amount_total` | decimal | `668.85` | контроль итоговой суммы |
| `actor` | enum | `system` | инициатор перехода |
| `at` | datetime | `2025-11-01T18:00:00Z` | время события |

## 5. Защита данных

**Нельзя хранить:**

- PAN/CVV клиента — не запрашиваются и не сохраняются.
- Полные реквизиты сотрудника — сохраняется только маска.

**Можно хранить:**

- `payment_details` — только `****NNNN`.
- `signature` — криптографический результат HMAC, не секрет.
- `nonce` — одноразовое публичное значение, не секрет.

**Маскирование логов:**

- До: `card=4100123412341001` — такая запись запрещена.
- После: `payment_details=****1001`.

## 6. Секреты и ключи

| Секрет | Где хранится | Кто имеет доступ | Ротация |
|-|-|-|-|
| HMAC-ключ | В production: серверный secret manager / переменная окружения | только платёжный backend | по регламенту и при компрометации |
| Пароль БД | Серверный secret manager / переменная окружения | только backend и администратор инфраструктуры | периодически и при смене доступа |

Секреты не коммитируются в Git и не пишутся в логи. В хакатон-демо HMAC-секрет находится в клиентском коде исключительно для воспроизводимости; это известное ограничение, а не безопасная production-схема.
