# Роли и права — кейс 3

## Матрица ролей

| Действие | Мерчант | Официант | Клиент | Администратор |
|-|-|-|-|-|
| Регистрация в платформе | да | по приглашению | не требуется | через отдельное назначение |
| Генерация QR на чек | да | да, только на себя | нет | нет |
| Просмотр своих чаевых | да, по заведению | да, только своих | нет | только аудит |
| Сканирование QR | нет | нет | да | нет |
| Оплата чаевых | нет | нет | да | нет |
| Просмотр отчёта по заведению | да, своего | нет | нет | да |
| Блокировка мерчанта | нет | нет | нет | да |
| Изменение справочников | своего заведения и команды | только своих данных | нет | всех |

## Регистрация мерчанта

| Шаг | Кто делает | Что происходит | Проверки |
|-|-|-|-|
| 1 | Мерчант | Отправляет название и описание заведения | Обязательные поля, длина 1–100 и 0–200 |
| 2 | Система | Создаёт запись мерчанта со статусом `PENDING` | Уникальный `merchant_id`; самостоятельная активация запрещена |
| 3 | Администратор | Проверяет заявку и активирует или блокирует заведение | Только права администратора |
| 4 | Система | При `ACTIVE` открывает генерацию QR и кабинет отчётности | Статус проверяется при каждой валидации QR |

## Регистрация сотрудника

1. Мерчант создаёт приглашение и одноразовый код для сотрудника.
2. Сотрудник вводит код; система привязывает его к `merchant_id` пригласившего заведения.
3. Система создаёт уникальный `employee_id`; сотрудник получает доступ только к своим чаевым и QR.
4. Реквизиты для выплат сохраняются только в маске `****NNNN`; полные значения и PAN/CVV не сохраняются.

## Критерий приёмки

- [x] Все 4 роли описаны.
- [x] Матрица заполнена: 8 действий × 4 роли.
- [x] Регистрация мерчанта описана в 4 шага.
- [x] Регистрация сотрудника описана в 4 шага.
- [x] Реквизиты маскируются.
- [x] QR клиента привязан к конкретному `receipt_id`.
