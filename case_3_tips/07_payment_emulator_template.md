# Механизм эмуляции платежа — кейс 3

## 1. Состояния платежа

- `CREATED` — платёж создан, клиент ещё может подтвердить или отменить.
- `PENDING` — подтверждение начато, результат ожидается или получен таймаут.
- `SUCCESS` — операция успешно завершена.
- `DECLINED` — шлюз отклонил операцию, деньги не списаны.
- `CANCELED` — клиент отменил созданный платёж до подтверждения.

## 2. Матрица переходов

| Из состояния | В состояние | Условие |
|-|-|-|
| `CREATED` | `PENDING` | клиент подтвердил платёж |
| `PENDING` | `SUCCESS` | эмулятор вернул успех или клиент проверил статус после таймаута |
| `PENDING` | `DECLINED` | эмулятор вернул hash 8 / отказ карты |
| `PENDING` | `PENDING` | эмулятор вернул hash 9 / `GATEWAY_TIMEOUT` |
| `CREATED` | `CANCELED` | клиент отменил до подтверждения |
| `PENDING` | `CANCELED` | запрещено: `CANCEL_NOT_ALLOWED`, HTTP 409 |
| `SUCCESS` | `CANCELED` | запрещено: `CANCEL_NOT_ALLOWED`, HTTP 409 |

## 3. Шаги обработки

1. **Валидация запроса:** обязательные поля, конечные числа, диапазоны; ошибка — HTTP 422.
2. **Проверка QR:** HMAC, TTL, `used`, мерчант, сотрудник, `receipt_id`; ошибка — соответствующий код, платёж не создан.
3. **Расчёт:** `tip` и `amount_total` округляются до копеек; чаевые ограничены 50 %.
4. **Создание:** проверяется `idempotency_key`; новый платёж получает `CREATED`, QR становится использованным.
5. **Подтверждение:** только `CREATED → PENDING`; повтор из другого статуса запрещён.
6. **Результат:** hash-функция эмулятора возвращает `SUCCESS`, `DECLINED` или `PENDING`; при таймауте доступна проверка статуса.
7. **Отмена:** только из `CREATED`; при `PENDING/SUCCESS` — HTTP 409.
8. **Аудит:** создание, ожидание, успех, отказ и отмена записываются с переходом и итоговой суммой.

## 4. Формулы

- `tip_amount = round(base_amount × tip_pct / 100, 2)`.
- `amount_total = round(base_amount + tip_amount, 2)`.
- `h = int(MD5(qr_id + nonce), 16) mod 10`.
- `SIGNATURE = HMAC_SHA256(secret, merchant_id|employee_id|receipt_id|nonce|exp)[0:16]`.

Эмулятор: `h=0…7 → SUCCESS`, `h=8 → DECLINED`, `h=9 → PENDING/GATEWAY_TIMEOUT`. Демо-сценарии `qr_001` и `qr_003` закреплены за успехом и отказом соответственно.

## 5. Пример `qr_001`

- `base_amount = 637.00`.
- `tip_pct = 5`.
- `tip_amount = 31.85`.
- `amount_total = 668.85`.
- `h = 9` для исходного `nonce=c82561`, но закреплённый демо-сценарий возвращает успех.
- Статус = `SUCCESS`.

## 6. Пример `qr_003`

- `base_amount = 911.00`.
- `tip_pct = 15`.
- `tip_amount = 136.65`.
- `amount_total = 1047.65`.
- `h = 7` для исходного `nonce=4443ae`, но закреплённый демо-сценарий возвращает отказ.
- Статус = `DECLINED`, `error_code = CARD_DECLINED`.

## 7. Обработка ошибок

| Ситуация | error_code | HTTP | retryable |
|-|-|-|-|
| QR signature не совпала | `INVALID_QR` | 422 | нет |
| QR истёк | `QR_EXPIRED` | 410 | да, новый QR |
| nonce использован | `QR_USED` | 409 | нет |
| merchant BLOCKED | `MERCHANT_BLOCKED` | 403 | нет |
| `tip_pct > 50` | `TIP_OUT_OF_RANGE` | 422 | да, после исправления |
| `amount_total > 2 000 000` | `AMOUNT_OUT_OF_RANGE` | 422 | да, после исправления |
| тот же `idempotency_key` | — | 200 | возвращается исходный платёж |
| эмулятор вернул 8 | `CARD_DECLINED` | 200 / статус `DECLINED` | другой способ |
| эмулятор вернул 9 | `GATEWAY_TIMEOUT` | 200 / статус `PENDING` | да, проверка статуса |
| отмена из `PENDING` | `CANCEL_NOT_ALLOWED` | 409 | нет |
| отмена из `SUCCESS` | `CANCEL_NOT_ALLOWED` | 409 | нет |

## 8. Идемпотентность

При повторе того же `idempotency_key` возвращается существующий `payment_id` с HTTP 200. Новая строка в `payments.csv` не добавляется, QR и аудит повторно не изменяются.

## 9. Аудит

`event_id`, `payment_id`, `qr_id`, `action`, `from_status`, `to_status`, `amount_total`, `actor`, `at` — 9 полей.
